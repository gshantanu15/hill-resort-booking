# Local setup

Use Node.js 24 and npm. Run `npm ci`, copy `.env.example` to `.env.local`, and run `npm run dev`. Without a database, the home page shows an explicitly labelled sample catalogue.

For Neon, create a development branch and a separate demo branch. Set the pooled connection in DATABASE_URL and direct connection in DATABASE_URL_UNPOOLED in the ignored `.env.local`. Use the development connection for local work; configure the demo connection in Vercel. Never paste connection strings into issues, documentation, or chat.

Run `npm run db:migrate` then `npm run db:seed`. For the demo branch, use an ignored `.env.demo.local` and set ENV_FILE to `.env.demo.local` for both commands. Never point routine local work at the demo branch. Seeding is repeatable and preserves existing room records. Day one creates only the room catalogue; booking inventory and staff tables arrive on day two. Do not use `drizzle-kit push` against the shared demo database.

Checks: `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test`, `npm run build`. Browser checks: install Chromium with `npx playwright install chromium`, then `npm run test:e2e`.

Database constraint tests: create an isolated Neon test branch from development and put its **direct** connection in `TEST_DATABASE_URL` in ignored `.env.test.local` (or supply that environment variable). Run `npm run test:db`. The command applies tracked migrations to that test database; synthetic test fixtures run inside transactions that roll back on success or failure. It never falls back to `DATABASE_URL`, rejects pooled connections, and fails if no explicit test URL is supplied. Never supply the demo/development application connection: migrations persist even though fixtures roll back. `ENV_FILE` can select a different ignored test env file. These tests are separate from `npm test` and are not yet run by CI. Renew test branch/credentials after branch expiry; see `docs/DAY_2_EVIDENCE.md` for this unit's environment.

Vercel: import gshantanu15/hill-resort-booking, retain automatic Next.js detection, configure the demo pooled DATABASE_URL as a production secret, pin Node 24, and deploy. The app uses the Singapore function region via vercel.json. For automatic deploys authorize the Vercel GitHub app for this repository, then run `npx vercel git connect --yes`. CLI deployment uses `npx vercel deploy --prod --yes`. A connection-backed catalogue must display “Room catalogue connected to PostgreSQL.” If the variable is missing, the site is a sample preview and day one's deployment criterion remains incomplete.

OpenRouter is configured with the owner-selected `google/gemma-4-26b-a4b-it:free` model. Set OPENROUTER_API_KEY, OPENROUTER_MODEL and OPENROUTER_FALLBACK_MODEL in ignored `.env.local` and Vercel production configuration. The approved fallback is `dots-studio/dots-3-note-preview:free`, verified on all four sample classifications. Run `npm run ai:check` only when deliberately testing live inference (up to four synthetic requests). Free quota is planned at 50/day and 20/min; provider capacity can still return 429. See [OpenRouter setup](OPENROUTER.md) for verification status and the paid-model guard. BETTER_AUTH_SECRET and BETTER_AUTH_URL are declared for day-two authentication; authentication is not implemented yet.

Design: read root DESIGN.md before frontend changes. npm ci retrieves and verifies the approved Sentient files from Fontshare; they are ignored in Git. npm run fonts:fetch can restore them locally. The initial font download requires network access. Hanken and all required licenses are included in public/fonts/.
